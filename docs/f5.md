## 介面範例

```python
from scheduler.models import Course, Student, SystemData, FilterCriteria
from scheduler.course_filter import filter_courses
from scheduler.filter_display import format_filter_report

data = SystemData(
    courses={
        "CS201": Course("CS201", "資料結構", 3, "required", "王老師",
                        30, "EE-101", ["1-3", "1-4"]),
        "EN110": Course("EN110", "英文寫作", 2, "elective", "李老師",
                        30, "LIB-101", ["3-7", "3-8"]),
    },
    students={"S004": Student("S004", "測試學生", "資工二", 24)},
)
criteria = FilterCriteria(
    desired_courses=["EN110"],
    required_courses=["CS201"],
    min_credits=5,
    max_credits=20,
    forbidden_slots=[f"5-{period}" for period in "123456789abc"],
    preferred_days=[1, 2, 3],
)
result = filter_courses(data, "s004", criteria)
# 在呼叫端／CLI 顯示：print(format_filter_report(result))
assert result.ok and result.data.feasible
assert result.data.available_credits == 5
```

`criteria` 也可傳入相同欄位的 dict。課程代號與學號忽略大小寫及前後空白；清單去重。學分須為非負整數，布林及小數拒絕；偏好星期僅接受 1–7 的整數。核心禁課欄位接受 `星期-節次` 清單，CLI 額外展開 `5-*` 之類的全天輸入。

## 回傳語意

- `Result.ok=True` 表示目前所有必要條件通過，`data.feasible=True`；沒有搜尋最佳課表，候選選修之間仍可能衝堂。
- `Result.ok=False` 且 `data` 存在：保留完整篩選結果，`errors` 是全部不可行原因。
- 格式錯誤、學生不存在、已選參照遺失或無法檢查已選時段時，回傳錯誤，`data=None`，不拋出例外到 CLI。
- `FilterReport.candidates` 是可加選候選；`excluded` 含各課全部 `reasons`；`already_enrolled` 是目前有效已選課程。
- `required` 標記依本次必修清單決定，與課程本身的 `type` 欄位不同。已選且在必修清單中的課程視為已滿足，不因自我衝堂或額滿而排除。
- `current_credits` 只算有效已選課程；`required_credits` 是已知必修課不重複的學分總和；`available_credits` 是已選學分加所有未排除的新候選學分，是寬鬆上界。
- 必修課彼此衝堂與必修超分檢查不因其他必修已被排除而略過。已選學分加新必修若超過最高學分，也會回報 `REQUIRED_EXCEEDS_MAX`。
- 偏好清單為空視為不限，因此每門可選課的 `preferred` 為 True。
- 不額外依教室衝突或單一候選加選後超學分排除課程；F5 的排除規則依 FR-5.2，正式加選仍須經 F2。

## 共用時間規則與相容層

`scheduler/conflict.py` 實作唯一時段交集與日期規則，使用 `(星期, 節次索引 0–11)`；兩個單次占用需同日期，課程／每週活動以 `date=None` 表示。取消活動不計入學生占用。活動沒有儲存時段時，由日期與時間換算。

既有 F2 經 `legacy_overlap()` 呼叫同一核心，F4 的日期判斷亦轉用同一核心，並讓取消活動釋放占用及拒絕重新報名。四個既有相關回歸測試已轉為通過。檔案損壞被舊 `loadData()` 當成空清單的問題仍由既有回歸測試保留警示。

`f5_system.filterCourses(studentId, criteria, courses, students, activities, classrooms)` 接收舊 JSON 清單或 v1 包裝；舊學生的 enrolledActivities 轉成活動 participants；不把新格式覆寫回既有檔案。

## 測試與執行

```powershell
python -m pip install -r requirements.txt
python -m pytest -v tests/test_f5_filter.py
python -m pytest tests/test_f5_filter.py -m normal
python -m pytest tests/test_f5_filter.py -m boundary
python -m pytest tests/test_f5_filter.py -m error
python run_tests.py
```

pytest fixture 每個案例提供獨立記憶體資料；CLI 測試使用 tmp_path。`run_tests.py` 合併根目錄 unittest 與 F5 pytest 報告，失敗時仍會輸出 HTML／JSON／文字報告。GitHub Actions 設定會安裝 requirements 並執行兩種工具，報告在失敗時亦會上傳。
