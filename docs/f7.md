# F7 最佳課表搜尋

## 規格依據與實作範圍



- 01requirementsSpecification：輸入指定必修、候選選修、學分範圍、禁止時段與偏好，搜尋所有可行課表並排序。必要條件為不衝堂、指定必修全數納入、學分上下限、不選額滿課、不在禁止時段；偏好為減少到校天數、空堂、早八、集中時段、提高偏好課程比例。
- 03systemArchitecture：`scheduler/optimizer.py` 依賴 F5 與共用 `conflict.py`，服務接收 `SystemData`、回傳 `Result`，不執行輸入輸出或檔案儲存。
- 04dataFormat：使用既有 Course、Student、Activity、Occupancy、Result、ErrorItem；人數由學生選課清單計算，不儲存衍生人數。
- 05workBreakdownStructure：3.12 評分函式與 TDD、3.13 偏好及限制資料、3.18 CLI 整合。



## 操作

```powershell
python main.py --init-demo --data-dir demo-data
python main.py --data-dir demo-data
```

選 **9. F7最佳課表搜尋**。示範資料不會覆寫既有檔案；如已有 demo-data，直接執行第二行。

若要使用專案根目錄的舊版 JSON，執行 `python f1_system.py` 選 **12**。

依序輸入：學號、候選選修、指定必修、最低總學分、最高總學分、禁止時段、偏好星期、偏好課程、顯示組數、六項權重。

- 代號以逗號或空白分隔，不分大小寫並去除前後空白。
- 候選取選修與指定必修聯集，重複代號只算一次；課程本身標為 required 不會自動加入，應在指定必修清單輸入。
- 總學分包含目前已選課程；最高學分留空採學生上限。已選課程固定保留，已選必修不重複計分，也不因本人已占最後一名額而被排除。
- 禁止時段如 `2-3,5-a`；`5-*` 表示星期五十二節全部禁止。此條件限制課程，已報名活動固定保留。
- 偏好星期如 `1,2,3`，為軟性評分，並不排除其他星期。
- 偏好課程留空採候選選修清單；API 可傳空清單表示不採偏好課程加分。
- 顯示組數預設 5；輸入 `all` 顯示所有可行解。組數只限制回傳數量，不限制搜尋或總解數統計。
- 權重依序為到校天數、空堂、早八、跨度、偏好課程、偏好星期；留空採 `5,2,3,1,10,5`。接受 0 到 1000000 的有限數值，拒絕負數、布林值、NaN、Infinity。

輸出完整可行解數、前幾名課程、建議加選、總學分、分項評分及星期一至日共十二節的課表。`*` 表示活動，單次活動另列日期；同星期不同日期的活動可能顯示在同一格，但不視為衝突。

搜尋只提供建議，不會自動加選、退選、報名活動、寫入選課歷程或存檔。唯讀工作階段也能搜尋，須以完整可用資料作為實際選課依據。

## 評分及同分排序

總分愈高愈優先；可為負數。以課程和已報名活動的每週占用聯集計算：

| 指標 | 定義 | 預設權重 |
| --- | --- | --- |
| D 到校天數 | 至少有一個占用的星期數 | 5 |
| G 空堂 | 每天首末占用之間未占用的節數總和 | 2 |
| E 早八 | 有第 1 節占用的天數 | 3 |
| S 跨度 | 每天最後節索引減第一節索引加 1，再加總 | 1 |
| P 偏好課程比例 | 選中偏好課程數 / 全部選中課程數，含已選；無課程或未設定偏好時為 0 | 10 |
| Q 偏好星期比例 | 在偏好星期的占用格數 / 全部占用格數；未設定偏好或無占用為 0 | 5 |

```text
score = -wD*D -wG*G -wE*E -wS*S +wP*P +wQ*Q
```

分數取至小數第 8 位再排名。依序比較：總分高、到校天數少、空堂少、早八少、跨度短、總學分高、完整課程代號序列字典序。固定排序可避免輸入順序影響結果。

空堂與跨度使用完整十二節順序 `1..9,a,b,c`；無占用的日子計 0。單次活動在其星期呈現，與 F3 的每週摘要方式一致；同一格只計一次占用。這是每週摘要評分，沒有依每個實際日期分開加權。

## 搜尋與錯誤

1. 呼叫 F5 篩選：收集不存在、取消、額滿、禁止時段、與已選課程或活動衝突等全部排除原因；偏好不排除課程。
2. 檢查所有必要條件：必修被排除、必修互相衝堂、學分矛盾等；額外檢查固定已選課表本身的衝堂、禁止時段與超學分。
3. 以回溯選擇每門候選課程。必修不可跳過；使用共用 `overlap_slots` 計算候選兩兩衝突，剪除衝堂、超過最高學分、剩餘課程全部加入仍低於最低學分的分支。
4. 每一個可行組合只計數一次；計算分數，保留排名前 k 組。`top_k=None` 時收集並排序全部解。

已報名活動固定保留，課程和每週活動與單次活動的日期衝突，全部沿用 `conflict.py`。單次活動同星期不同日期不衝突，課程一律每週重複。

F5 的「可能可行」不代表真正存在解。若候選總學分足夠但彼此衝堂而無任何合法組合，F7 回傳新增的 `NO_FEASIBLE_TIMETABLE`。其他錯誤沿用 F5 的錯誤代碼與 `CREDIT_LIMIT_EXCEEDED`、`STUDENT_TIME_CONFLICT`、`ACTIVITY_TIME_CONFLICT`、`FORBIDDEN_SLOT`；所有違規與排除原因均保留。

最低學分為 0 且無必修或已選時，空課表是合法解；若希望至少選一門，請設定正的最低學分。

完整搜尋最壞為指數時間。預設只保留前 5 組節省結果記憶體，仍須搜尋所有可行組合；未設時間上限，也不會將部分結果宣稱為最佳解。`visited_nodes` 是本次回溯進入狀態的次數，包含進入後被學分界限剪除的狀態；F8 後續可另外定義比較口徑。

## 服務介面

```python
from scheduler.models import FilterCriteria, ScoreWeights
from scheduler.optimizer import search_best_timetables
from scheduler.optimizer_display import format_optimizer_report

result = search_best_timetables(
    data, "S001",
    FilterCriteria(
        desired_courses=["CS102", "EN101"],
        required_courses=["CS101"],
        min_credits=6, max_credits=12,
        forbidden_slots=["5-a"], preferred_days=[1, 2, 3],
    ),
    weights=ScoreWeights(),
    preferred_courses=["CS102"],
    top_k=5,
)
# 在 CLI 顯示 format_optimizer_report(result)
```

`Result.data` 為 `OptimizerReport`：`filter_report`、`weights`、`preferred_courses`、`top_k`、`feasible_count`、`visited_nodes`、`schedules`。每組為 `ScheduleOption`：`course_codes`（全部課程）、`added_courses`（建議新增）、`total_credits`、`score`、`occupancies`。輸入格式錯誤時可能沒有報告，應先檢查 `result.data`。

舊資料入口：`f7_system.searchBestTimetables(studentId, criteria, courses, students, activities, classrooms, *, weights=None, preferred_courses=None, top_k=5)`，接受舊 camelCase 清單與 `schema_version=1, records` 包裝。
