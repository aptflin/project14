# F6 資料儲存與系統測試

## 依據與需求對照

依 `01requirementsSpecification_v1.pdf` 第 10–11 頁、`03systemArchitecture_v1.pdf` 第 4–7 頁、`04dataFormat.pdf` 第 1–7 頁及 `05workBreakdownStructure.pdf` 的 WBS 3.11、3.18、4.1、4.2、4.4 實作。

| 規則 | 實作 | 驗證 |
| --- | --- | --- |
| FR-6.1 | 五個 JSON，UTF-8、ensure_ascii=False、indent=2、schema_version=1 與 records | 五類往返、中文與格式測試 |
| FR-6.2 | main.py 啟動時 load_all；缺檔以空資料開始，載入報告列出 FILE_NOT_FOUND | 缺全部或部分檔案測試 |
| FR-6.3 | JSON 語法／編碼毀損，以 `.corrupt-時間戳-識別碼` 保留原檔，程式繼續啟動 | 毀損、NaN、備份失敗測試 |
| FR-6.4 | 單筆欄位驗證、型別防護與原始紀錄序號；保留有效資料 | 缺欄位、錯型別、非法時段、重複與深層型別案例 |
| FR-6.5 | 移除不存在／取消的已選參照；移除不存在報名學號；錯誤歷程略過 | 參照警告及混合五種錯誤測試 |
| FR-6.6 | 全部暫存檔完成並 fsync 後，再逐檔 os.replace；可捕捉失敗時復原 | 暫存失敗、第三檔失敗、首次建立失敗、序列化失敗 |
| FR-6.7 | CLI 先對複本執行業務，再儲存五檔；成功後才提交記憶體 | 加退選、活動報名取消、CLI 重啟及寫入失敗測試 |
| FR-6.8 | pytest normal／boundary／error，兩份 F6 測試檔合計至少 30 項，各類至少 10 項 | 一鍵測試與分類驗收報告 |

WBS 的儲存與測試產出均有程式及測試；不代填成員回覆、審查核准或團隊提交紀錄。本次變更存於本機，未推送 GitHub。

## 操作

在專案目錄執行：

```powershell
python main.py
```

預設讀取 `data/`。若尚未準備 v1 檔案，可建立獨立示範資料，再啟動：

```powershell
python main.py --init-demo --data-dir demo-data
python main.py --data-dir demo-data
```

示範資料為固定的 20 課、15 生、5 教室、10 活動，方便重現。初始化只允許五個目標檔皆不存在時執行。可用以下流程驗證自動儲存：

1. 選 `2`，輸入學號 `S001`、課程 `CS101`，看到「操作成功，已儲存五類資料」。
2. 選 `0`，重新執行同一個 `--data-dir`。
3. 選 `1` 查看 CS101 已選人數，或用 `5` 開啟 F5 查看目前學分。
4. 選 `3`、`S001`、`CS101` 退選；enrollments.json 會保留 add 並追加 drop。
5. 選 `4`、`S001`、`EV001` 報名，再用 `7`、`EV001` 取消活動，參加者名單亦會自動儲存。

選單還提供 `6` 資料數量摘要、`8` 手動儲存。讀取失敗／毀損／版本不支援時仍能查詢，但暫停修改與手動儲存；請先查看載入報告與備份，修復後重新啟動。

既有 `python f1_system.py` 仍操作根目錄的舊 camelCase 清單，不自動修改代號或轉成 v1。其輸入輸出已搬至 scheduler/cli.py，檔案讀寫集中由 storage.py 處理。舊格式也使用暫存原子取代與讀取錯誤保護；完整五檔 v1 自動儲存及歷程使用 main.py 入口。

## 模組與介面

- `models.SystemData` 為共用資料容器；`StorageSystemData` 保留為別名。Course、Student、Activity 載入為資料類別，並相容舊 `record["field"]` 取值。活動時段快取不寫入 JSON。
- `load_all(data_dir="data") -> (SystemData, LoadReport)`：不輸出畫面。報告含各檔讀取數、成功數、略過項目、檔案錯誤、備份檔名及參照警告。
- `save_all(data, data_dir="data") -> SaveResult`：SaveResult 繼承 Result，可用 `.ok`／`.errors`，亦可用舊 `ok, message = ...` 拆包。
- `validators.py`：單筆純欄位驗證。服務資料型別錯誤不會中止整批讀取。
- `storage_bridge.py`：v1 與既有 F1–F5 的純記憶體轉接，participants 是活動報名的儲存來源，不把衍生名單重複存到學生。
- `operations.py`：對複本做業務操作；不呼叫 input／print 或執行檔案 I/O。加退選追加 UTC ISO 8601 歷程。
- `cli.py`：顯示報告與選單、呼叫服務與儲存。儲存失敗不提交記憶體修改。

所有有效既有選課歷程只允許追加，save_all 會拒絕修改或刪除。依 FR-6.5，已損壞或參照不存在的歷程可在載入時略過，不作為有效歷程前綴。

儲存層不代替各業務服務的規則驗證：正常修改須先通過 F1／F2／F4 檢查。載入時則重新驗證所有紀錄。測試可刻意寫入不合法紀錄，驗證載入器的容錯行為。

## 檔案復原

資料檔毀損時原始內容以 `.corrupt-...` 保留；若無法搬移，原檔不刪除，錯誤會寫入報告。合法 JSON 的版本／外層格式錯誤不改名，直接回報並阻止該次 CLI 寫入。

save_all 會先序列化全部內容，再建立五份新暫存檔與原檔復原副本。取代階段遇到可捕捉的錯誤時，已取代者用副本復原；首次建立的檔案則移除。若復原本身也失敗，保留 `.rollback_*.json`，並在 SAVE_FAILED 訊息列出路徑，供人工復原。

此機制提供單檔原子取代與執行期失敗的還原，未宣稱作業系統突然斷電時五個檔案具備資料庫式的跨檔案交易保證。

## 測試與證據

```powershell
python -m pip install -r requirements.txt
python -m pytest -v tests/test_f6_storage_and_system.py tests/test_f6_robustness.py
python -m pytest -m normal tests/test_f6_storage_and_system.py tests/test_f6_robustness.py
python -m pytest -m boundary tests/test_f6_storage_and_system.py tests/test_f6_robustness.py
python -m pytest -m error tests/test_f6_storage_and_system.py tests/test_f6_robustness.py
python run_tests.py
```

測試只用記憶體、tmp_path 與暫存資料夾；包含故障注入，不讀寫正式根目錄 JSON 或 data/。既有五種錯誤情境、壞檔及自動儲存皆可重現。`test-results/report.html`、`results.json`、`results.txt`、`pytest.xml` 為完整測試證據；`f6-acceptance.json` 記錄 F6 分類數量。
